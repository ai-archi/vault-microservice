## 组件设计原则

1. **单一职责**：每个组件只负责一个明确功能。
2. **可复用性**：组件可在多种场景下复用，通过 Props 配置行为与展示。
3. **可组合性**：组件可与其他组件组合，支持复杂 UI 构建。
4. **可访问性**：组件支持无障碍访问，符合 WCAG 标准（ARIA、键盘导航等）。

## 组件开发规范

- **API 设计**：Props/Events/Slots 命名清晰，必填与可选区分明确；类型与默认值在文档与代码中一致。
- **样式与主题**：通过设计令牌（颜色、间距、圆角、阴影）与主题变量定制，避免硬编码样式。
- **状态与副作用**：组件内部状态最小化；与全局状态/应用层交互通过 Props 或 Context/Store 明确约定。
- **测试**：基础组件与核心业务组件需具备单元测试（渲染、Props、事件、可访问性）；复杂交互建议集成测试。

## 与设计系统/主题的关系

- 组件库（{{uiComponents}}）提供基础设计令牌与主题（亮/暗、间距、字体等）。
- 业务组件与布局组件在基础组件之上封装，仍遵循同一套设计规范与主题变量。
- 国际化（i18n）通过文案 key 或 Props 注入，不写死在组件内。
