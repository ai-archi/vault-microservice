## 概述

本文档描述 {{serviceName}} 微服务的共享模块概览，包括共享模块的定义、定位和列表。

共享模块是跨领域的技术性共享能力，提供技术组件和服务，不包含业务逻辑，可以被多个业务领域复用。

## 共享模块定义

### 模块定位

共享模块是**技术性共享能力**，主要负责：

- **技术组件**：提供跨领域的技术组件（如应用总线、事件总线等）
- **技术服务**：提供跨领域的技术服务（如消息路由、协议转换等）
- **技术能力**：提供可以被多个业务领域复用的技术能力
- **架构支持**：为系统架构提供技术支持和基础设施

### 模块特点

共享模块具有以下特点：

- **技术导向**：纯粹的技术实现，不包含业务逻辑
- **跨领域复用**：可以被多个业务领域复用
- **架构定位**：位于架构的技术层，为业务层提供技术支持
- **独立部署**：可以独立部署和维护

### 模块边界

**共享模块包含**：

- ✅ 技术性共享组件（如应用总线、事件总线等）
- ✅ 跨领域的技术服务（如消息路由、协议转换等）
- ✅ 技术性共享能力（如事件发布订阅、命令路由等）

**共享模块不包含**：

- ❌ 业务领域的聚合和实体（属于各自的业务领域）
- ❌ 业务逻辑和业务规则（属于业务领域）
- ❌ 基础设施层技术工具（属于基础设施层）
- ❌ 数据访问抽象（属于基础设施层）

## 架构定位

### 在系统架构中的位置

共享模块位于系统架构的技术层，为业务层提供技术支持：

```
┌─────────────────────────────────────┐
│  业务领域层（Business Domain）      │
│  知识体系域、学习路径域等           │
└──────────────┬──────────────────────┘
               │ 使用
┌──────────────▼──────────────────────┐
│  共享模块层（Shared Modules）       │
│  应用总线、事件总线等               │
└──────────────┬──────────────────────┘
               │ 使用
┌──────────────▼──────────────────────┐
│  基础设施层（Infrastructure）        │
│  技术工具、数据访问等                │
└─────────────────────────────────────┘
```

### 与业务领域的关系

共享模块为业务领域提供技术能力支持：

- **技术能力提供**：为业务领域提供技术组件和服务
- **跨领域复用**：可以被多个业务领域复用
- **架构解耦**：通过技术抽象实现业务领域与技术实现的解耦

### 与基础设施层的关系

共享模块与基础设施层的关系：

- **技术依赖**：共享模块可能依赖基础设施层的技术工具
- **职责区分**：共享模块提供跨领域的技术组件，基础设施层提供通用的技术能力
- **架构分层**：共享模块位于业务层和基础设施层之间

## 设计原则

共享模块遵循以下设计原则：

- **技术导向**：纯粹的技术实现，不包含业务逻辑
- **可复用性**：可以被多个业务领域复用
- **接口抽象**：通过接口定义提供技术能力，隐藏实现细节
- **独立部署**：可以独立部署和维护
- **版本管理**：可以独立进行版本管理
